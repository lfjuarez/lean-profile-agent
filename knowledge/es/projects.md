## IA agéntica aplicada a ciberseguridad

Lo desarrollé yo, en mi rol actual, con el objetivo de que migrar y mantener reglas de detección entre SIEM sea rápido, consistente y medible. El problema: migrar y mantener miles de reglas de detección entre plataformas SIEM a mano es lento, inconsistente y deja reglas muertas que nunca disparan. Lo que construí, en mi rol actual: pipelines en Python basados en agentes de IA que migraron más de 2.000 reglas de detección entre plataformas SIEM. Cada regla pasa por control de calidad automático, enriquecimiento de metadatos y mapeo a MITRE ATT&CK, con una evaluación automática de cobertura y obsolescencia; las reglas que no cumplen el estándar quedan en cuarentena en lugar de migrarse tal cual. La calidad se garantiza con una batería de tests automática (vía MCP) y un seguimiento de cobertura por metadatos contra MITRE ATT&CK y ATLAS. Para investigaciones y validación de consultas uso el MCP nativo de Elastic más un MCP propio en Python con skills reutilizables que migran y escriben detecciones bajo estándares estrictos. También contribuí a una herramienta de IA que detecta huecos de cobertura MITRE ATT&CK y ATLAS y genera y prueba reglas de detección UEBA, y construyo asistentes conectados a Splunk, Elastic y Jira mediante el Model Context Protocol (MCP). El objetivo es siempre el mismo: agentes que hagan la ingeniería de detección más rápida y confiable, con una persona revisando lo que importa.

## mitre-coverage-kit (código abierto)

Lo desarrollé yo como proyecto de código abierto, con el objetivo de que un SOC pueda medir su cobertura de detección en lugar de suponerla. El problema: la cobertura de detección suele ser una creencia ("cubrimos credential access") que nadie puede medir. mitre-coverage-kit la convierte en una medición. Es una herramienta en Python (`coveragekit`) que lee las reglas de uno o varios SIEM, desde archivos exportados o directamente desde sus APIs (Splunk Enterprise Security, Elastic Security, Wazuh, Microsoft Sentinel o Sigma), puntúa cada técnica de MITRE ATT&CK Enterprise y de MITRE ATLAS de 0 a 3 con un semáforo suave (sin cobertura, baja, media, alta, con marcas aptas para daltonismo), exporta una capa para ATT&CK Navigator y un mapa de calor en SVG, y genera informes en HTML, PDF, Excel, CSV, Markdown y JSON. También lista las reglas muertas: las que están habilitadas pero nunca podrían disparar porque falta su fuente de datos. Con `coveragekit serve` levanta una aplicación web local que refresca cada fuente según un cronograma y deja que el SOC navegue el resultado: cifras clave y su variación, cobertura en el tiempo y por fuente, las matrices completas de ATT&CK y ATLAS con filtros, un panel por técnica con sus reglas, los datos que le faltan a cada una y sus tests de Atomic Red Team, recomendaciones, historial con diff entre refrescos y exportación. Los catálogos (por ejemplo, el repositorio SigmaHQ) son reglas disponibles pero no desplegadas: nunca cuentan como cobertura, pero para cada técnica sin detección se listan las reglas públicas que la cubrirían, primero las que leen datos que ya se recolectan. Incluye ATT&CK Enterprise v20 y ATLAS v5.6, un laboratorio que corre los importadores contra Splunk, Elastic y Wazuh reales en contenedores, y se probó contra el ruleset completo de Wazuh (4.499 reglas) y el repositorio público de SigmaHQ (3.162 reglas). Algo similar, a escala masiva, lo implementé en empresas muy grandes: medición y seguimiento de cobertura sobre SIEM de distintos proveedores y en distintos entornos (cloud, on-premise e híbridos), con una batería de tests automática y seguimiento de cobertura por metadatos. Licencia MIT, con tests e integración continua en cada push. Código: github.com/lfjuarez/mitre-coverage-kit.

## splunk-mcp-readonly (código abierto)

Lo desarrollé yo como proyecto de código abierto, con el objetivo de que un asistente de IA pueda consultar Splunk sin ningún riesgo de escribir, borrar o ejecutar algo. El problema: un asistente de IA que puede explorar Splunk es útil; uno que puede ejecutar `| delete` o `| outputlookup` por un error o una inyección de prompt es un incidente. splunk-mcp-readonly es un servidor MCP independiente y de solo lectura que permite a Claude Desktop, Claude Code o cualquier cliente MCP consultar Splunk Enterprise y Splunk Cloud con solo un token, sin instalar nada en el Splunk del cliente: corre del lado del consultor, el auditor o el analista y solo necesita el puerto de administración. Expone siete herramientas de solo lectura (búsqueda, validación de SPL sin ejecutarla, índices, saved searches, información del servidor, salud y notables de Enterprise Security) detrás de una guarda que rechaza cualquier comando que pueda escribir, borrar, exportar o ejecutar, fuerza un tope de filas y un rango de tiempo por defecto, aplica una lista de índices permitidos y escribe un registro de auditoría en JSON Lines de cada llamada. La seguridad se aplica dos veces: en el servidor y en el rol de Splunk con mínimos privilegios detrás del token. Unas 800 líneas de Python revisables en una hora, 83 tests sin conexión, licencia MIT. Código: github.com/lfjuarez/splunk-mcp-readonly.

## Arquitectura de referencia multi-site de Splunk (8 TB por día)

Lo diseñé y publiqué yo, con el objetivo de mostrar cómo se construye una plataforma Splunk que sobrevive a la pérdida de un centro de datos. Un diseño de referencia publicado para una plataforma Splunk Enterprise multi-site de alta disponibilidad y recuperación ante desastres, dibujado según los patrones de Splunk Validated Architectures: fuentes de datos y capa de recolección, cluster de indexers en dos sitios con factores de replicación y búsqueda, search head cluster multi-site, cluster dedicado para Enterprise Security, redundancia del cluster manager, SmartStore sobre almacenamiento de objetos con replicación entre regiones, plano de gestión, copias de seguridad y un runbook de failover ensayado. Los tamaños son representativos. El caso de estudio de la plataforma de dos sitios de este sitio muestra el mismo enfoque aplicado a un cliente representativo, con cifras sintéticas y método real.

## PresupuestAR, mi producto propio

Lo diseñé, desarrollé y opero yo, con el objetivo de que profesionales y oficios creen y envíen presupuestos profesionales en minutos y sepan cuándo el cliente los ve y los firma. Un proyecto propio que desarrollo por gusto: un SaaS web, en beta desde 2026 y aún sin lanzamiento oficial, para que profesionales y oficios creen y envíen presupuestos profesionales. El cliente recibe un enlace, ve el presupuesto y lo firma desde el teléfono. Funciones: presupuestos con PDF de diseño propio, envío por enlace con aviso cuando el cliente lo ve y lo firma, firma del cliente, consulta de datos del cliente por CUIT en la API de ARCA (el organismo fiscal argentino), logos e identidad del negocio, importación de ítems desde planillas y copias de seguridad automáticas. Tiene su propia mascota, Presu. Stack: Next.js, PostgreSQL con Prisma, Google Cloud Run con despliegue continuo, generación de PDF, integración con la API de ARCA. Es mi prueba de que diseño, construyo y opero software de punta a punta, no solo prototipos. Sitio en beta: presupuestarapp.com.

## Este sitio

Lo desarrollé yo, con el objetivo de tener un CV al que se le pueda preguntar y que responda solo con mi experiencia documentada, y de mostrar en público cómo trabajo con IA y MCP. Este CV es en sí mismo un proyecto: un chat que responde solo con mis documentos curados, citando documento y sección en cada respuesta, más un servidor MCP de solo lectura que expone la misma base de conocimiento. Cómo funciona: la base son documentos en español e inglés divididos en secciones; una búsqueda léxica (BM25) elige las secciones relevantes para cada pregunta; un modelo de lenguaje responde únicamente con esas secciones y las cita; si ninguna sección es relevante, el servidor declina sin llamar al modelo. La respuesta se transmite por streaming y la página marca qué secciones se leyeron y cuáles se citaron. Stack: Python con FastAPI, retrieval propio, proveedor de modelo configurable (Gemini en su nivel gratuito o Claude), servidor MCP con transporte Streamable HTTP y seis herramientas de solo lectura, límites de uso por IP y un tope diario, tests e integración continua, desplegado en Google Cloud Run bajo el dominio leandrojuarez.info. El código está abierto en github.com/lfjuarez/lean-profile-agent.
